# 差异化清单：本分支相对上游做了什么

> 更新日期：2026-11-15 · 适用版本 **v1.25（`cn-1.25`）**
> 定位不是「翻译版 / 镜像版」，而是**可检索的差异化**：每一项都对应一个具体痛点。
> 上游功能不在此表内，见 [`../UPSTREAM.md`](../UPSTREAM.md) 的版本审计。

命名对照（`v1.0~v1.4` 旧名 → `v1.5` 新名）见 [`RELEASE.md`](RELEASE.md) 的「重新命名」一节。

> **v1.9 开箱即用（v1.10 保留）**：识别行为**永久固定**——点一下棋盘＝这一帧直接算 → 支招 → 语音播报，
> 不点棋盘完全不动。v1.5~v1.8 的四选一互斥 / 两维度档位**全部取消**（用户原话：
> 「那么多复杂的设置我也看不懂啊，有必要吗？……我要的就是能用」）。
> 那些档位会把点棋盘劫持成「切候选」，把识别推理支招播报整条链断掉，实测即「点一下没用」。
> 打包前由 CI 强制跑 `TapChainTest` 端到端链路自检，走不通不出包。下表「开关」列按 v1.9 口径更新。

> **v1.24 点后新采帧 + 不回退上一局面**：点一下先丢弃点前残留缓冲帧、强制重提交一帧；修补层不再补漏检子（那会把对方刚走的一步撤销成上一手），只纠正车卒不分，并判定真实走子 / 认不全。引擎每次都从当前这一帧的全量 FEN 全新起算。

> **v1.23 单帧识别修补**：合法性检查只查「多认子」，漏一个车 / 车卒不分照样合法；用上一确认局面当锚，把孤立漏检与同阵营类别混淆就地补回，宁可不出招也不按错棋盘瞎指挥。

> **v1.22 点按档回到单帧直出**：原作者 3 帧确认只用于常开档；点一下棋盘不动，用那一帧直接算。
> 悬浮面板引擎芯片合并为红/黑两个大方块（互斥直选）；主页「一键关闭共享屏幕」一律执行停止。

> **v1.21 回到原作者口径**：点一下后连续 3 帧逐格一致才建局；本局面只发一次完整搜索，
> 只念这一轮 bestmove 定着✓；预判计算与对方回合搜索全部删除。

> **v1.20 招法质量门槛**：不再念引擎第一条浅 PV（07:58 日志 28/28 全是「暂定」）；
> 定着零等待、其余等 1s 且深≥8，2.5s 硬预算必出声；裁剪用上一局面保住真棋子。

> **v1.19 出声回执自愈**：speak 成功不等于真出声；1.5s 无 onStart 即重建 TTS 补念，
> 日志按真实回执写，不再冒功；证实「切红黑后不读」与切换无关。

> **v1.18 点一下就出声**：YOLO 多认 1 子按置信度就地裁掉、点击瞬间擦旧箭头、
> 2.5s 硬预算必有声音、回到单帧直出。真机 19 次点按成功率由 42% 起大幅回升。

> **v1.17 去掉用不了的选项**：ONNX 模型不随包、选了必回跳，还会清空棋盘状态 →
> 配置/连线页/悬浮面板三处固定 YOLO；两帧一致 + 与上一局面一步校验，可疑帧不支招。

> **v1.16 点一下就顺**：38 次真机点按实测 53% 被单帧门槛否决 → 700ms 内最多再抓 3 帧、
> 取首个合法帧；播报切入点从「定着 1.2s」改到「箭头出现」，念完锁定面板。
> 日志补「不合法明细」与「箭头→播报」耗时。

> **v1.15 签名固定**：三个历史包实测三把不同证书 → 显式注入固定 release 密钥 +
> 出包前证书指纹硬门禁（不一致禁止发布）。v1.15 起各版本可直接覆盖安装。

> **v1.14 插入点修正**：点棋盘不再拿点击前缓存帧，改为**点击瞬间主动抓当前屏幕这一帧**；
> 空闲态每帧无条件刷新缓存（象棋小帧差不再丢），点击后第一帧绕过帧节流/帧差阈值/节拍器直投识别。
> 识别完支招、念招是自然链路，不额外干预。

> **v1.13 换盘串色可手动定色**：悬浮面板原「哈希」按钮改为「我方 红/黑」互斥切换，
> 点一下锁定，跨对局、跨服务重启保持；自动判定的「屏幕下方」和新对局重定都翻不动。
> 解决「第一盘黑、第二盘红仍按黑支招」；哈希固定默认 256MB 不再可点。

> **v1.12 把不必要的等待砍掉**：逐条核对 18:41 真机日志（20 次点按 3~12.5 秒）后确认，
> 原作者 `mySideIsRed()` 本就按「屏幕下方＝我方」**单帧定敌我**，多帧确认是给自动档设计的，
> 点按场景纯属白等。回到单帧但保留全部正确性（合法门槛 / 我方锁定 / 起点双保险 / 只念一招），
> 预计延迟降到 1.5~2.5 秒；定着超时必给一招，修掉 5/20「有时不读」；一键关录屏改全局兜底。

> **v1.11 回到原作者管线（用户要求「去看原作者的代码，在原作者代码基础上做」）**：
> 拉了上游 `Silva6c/chess-dike` v3.4 源码逐行对照，确认 `handleFrame → tracker.onFrame`
> 的**合法性校验 + 连续 N 帧一致确认 + movedSide 轮次推断 + onSearchUpdate 定着**才是
> 支招的正确入口。v1.7~v1.10 为「快」另起单帧旁路把它全绕过了，于是真机日志里
> 「合法=false / ⚠不确凿照样支招」「一次点按念 3~6 个来回横跳的暂定着法」。
> v1.11 删除旁路、恢复上游确认链；只保留点按开闸口、我方锁定、一次点按只念定着一招。

> **v1.10 修「敌我不分」**：v1.9 单帧直出为了快把轮次推断砍了，FEN 永远按「红先」写；
> 我方阵营又每帧采信备用 YOLO 识别的朝向，一判反就把**对方棋子**的着法当成建议。

## 为什么这些算「差异化」而不是「汉化」

- 没有一处是翻译 README 或改命令名：全部是可运行、可开关、可单测覆盖的工程改动。
- 识别方式四档改变了**主循环的触发模型**（`ScreenAssistService` 的识别闸口），不是皮肤。
- 中文播报链路（清洗 → 分类 → 位掩码 → TTS → 诊断导出）是独立新增模块，与上游识别/引擎代码解耦。
- 包名锁定与固定签名是**发布链**改动，直接决定用户能不能覆盖升级，配有 CI 门禁。

## 明确不做的事

- 不做自动走子 / 触摸注入 / 无障碍服务：上游的只读合规底线，本分支完整保留。
- 不分发上游受版权保护的 ONNX 模型与桔库开局库；缺失时按上游设计自动降级。
- 不冒充官方签名版，不继承上游 v3.2+ 签名核验安全线（见 README 与 `UPSTREAM.md`）。
- 不追加上游 v3.4「学习模式」等大功能：同步策略见 `UPSTREAM.md`，采用人工逐项评估，不自动 merge。
