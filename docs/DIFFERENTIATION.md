# 差异化清单：本分支相对上游做了什么

> 更新日期：2026-11-15 · 适用版本 **v1.9（`cn-1.9`）**
> 定位不是「翻译版 / 镜像版」，而是**可检索的差异化**：每一项都对应一个具体痛点。
> 上游功能不在此表内，见 [`../UPSTREAM.md`](../UPSTREAM.md) 的版本审计。

命名对照（`v1.0~v1.4` 旧名 → `v1.5` 新名）见 [`RELEASE.md`](RELEASE.md) 的「重新命名」一节。

> **v1.9 开箱即用**：识别行为**永久固定**——点一下棋盘＝这一帧直接算 → 支招 → 语音播报，
> 不点棋盘完全不动。v1.5~v1.8 的四选一互斥 / 两维度档位**全部取消**（用户原话：
> 「那么多复杂的设置我也看不懂啊，有必要吗？……我要的就是能用」）。
> 那些档位会把点棋盘劫持成「切候选」，把识别推理支招播报整条链断掉，实测即「点一下没用」。
> 打包前由 CI 强制跑 `TapChainTest` 端到端链路自检，走不通不出包。下表「开关」列按 v1.9 口径更新。

## 为什么这些算「差异化」而不是「汉化」

- 没有一处是翻译 README 或改命令名：全部是可运行、可开关、可单测覆盖的工程改动。
- 识别方式四档改变了**主循环的触发模型**（`ScreenAssistService` 的识别闸口），不是皮肤。
- 中文播报链路（清洗 → 分类 → 位掩码 → TTS → 诊断导出）是独立新增模块，与上游识别/引擎代码解耦。
- 包名锁定与固定签名是**发布链**改动，直接决定用户能不能覆盖升级，配有 CI 门禁。

## 明确不做的事

- 不做自动走子 / 触摸注入 / 无障碍服务：上游的只读合规底线，本分支完整保留。
- 不分发上游受版权保护的 ONNX 模型与桔库开局库；缺失时按上游设计自动降级。
- 不冒充官方签名版，不继承上游 v3.2+ 签名核验安全线（见 README 与 `UPSTREAM.md`）。
- 不追加上游 v3.4「学习模式」等大功能：同步策略见 `UPSTREAM.md`，采用人工逐项评估，不自动 merge。
