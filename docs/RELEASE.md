## v1.5 更新内容

### 1. 所有分支功能集中一页：增强功能

主页只留**一个「增强功能」入口**，进去是一页式开关台：本分支相对上游自研的功能**每项都有独立开关**，改完即时生效。

- **识别方式（四选一互斥）**：呈现为四个「开/关」按钮，把想要的那一档点成「开」，其余自动变「关」。四档是 `点按出招`（默认）/ `点按刷新` / `点按变招` / `自动识别`。
- **自动识别时的点棋盘行为**：点按刷新 开/关（仅自动档生效）。
- **中文播报**：支招播报总开关、播报引擎、播报内容 5 项多选、试听。
- **诊断与工具**：增强功能诊断开关、自选路径导出 MD、清空日志。
- **构建期固定项**（只读）：包名锁定 `com.xqdk.chess`、固定签名——这两项是出包时锁死的，App 内不提供开关，页面里明确标注。
- 识别引擎 / 思考制式 / 局面预判 / 性能诊断 / 悬浮窗主题属**上游原有功能**，开关仍在连线主页，未收进本页（避免两处重复、避免和上游行为打架）。

### 2. 四档识别方式：默认仍「不点不动」，但这次回得去

- **点按出招（默认）**：不点棋盘＝零识别、零推理、零支招、零朗读；点一次棋盘＝抓当前画面识别一轮 → 多帧确认 → 开局库/皮卡鱼支招 → 中文播报，确认后立刻收场。10 秒确认不了自动收场并提示再点一次。
- **点按刷新 / 点按变招**：不点棋盘同样零识别；点一次分别等于右列「更新」键 / 切换候选着法。
- **自动识别**：恢复上游的连续识别（画面变化即推理，长时间发热明显），**非默认**。前三档由会话闸口控制，自动档闸口常开、无超时、确认后不收场。
- 手动摆棋模式下点棋盘始终是选子/走子，任何档位都不抢这次点按。

### 5. 修复：点棋盘没反应 + 诊断日志终于有参考价值

**用户实测问题**：装 v1.4 后点悬浮窗棋盘没反应、原有支招也消失；附的旧诊断文件
`XQDK_语音诊断_20261115_140310.md` 只有 3 行 TTS 事件（服务 onCreate / 引擎枚举 / 导出），
完全看不出点按、识别、支招哪一步断了。

**根因**：v1.4 一点棋盘就 `tracker.reset()` + `resetSuggestionState()`，把已确认局面和
已有支招清空，还强制要求重新凑满确认帧数产出 `NEW_BOARD` 才支招。静止画面、识别器缺
模型或棋盘被遮挡时确认链迟迟凑不满，超时后整屏空白。

**修复**：

- 点棋盘**保留**已有局面与支招，先按当前局面立即支招一次 → 点一下必有反馈；同时开
  识别闸口跑一轮识别。
- 画面没变 → `SAME_BOARD` 立即收场；画面变了 → `NEW_BOARD` 用新局面再支招一次。
- 识别失败 / 6 秒超时 → 按当前局面兜底支招，绝不留空白，并提示「本轮未重新识别，
  已按当前局面重新支招」。会话超时从 10s 收到 6s。
- **不点棋盘仍是零识别 / 零推理 / 零支招 / 零朗读**，语义不变。

**诊断日志扩展到覆盖本分支全部改动链路**：配置快照（版本 / 包名 / 识别方式 / 各开关）、
面板动作（点棋盘是否派发到服务）、点按出招会话（启动 / 拒绝原因 / 首帧可用 / 完成 /
超时兜底）、识别闸口、识别帧丢弃原因去重、识别引擎加载与回退、棋盘确认、支招调度、
状态文案、配置变更、导出事件。导出文件 `XQDK_增强功能诊断_*.md`，头部带「诊断覆盖」
一行与当前识别方式。隐私边界不变：只记事件与配置状态，不记帧像素、FEN 内容、对局、
引擎 PV 明细或性能数据。

> 排查「点棋盘用不了」现在先看日志里三行：`面板动作`（手势到没到）、`点按出招`
> （会话开没开 / 首帧在不在）、`识别帧`（帧被谁拦下）。

## 使用前须知

- **签名为本分支固定的 debug 签名**：不持有上游官方发布密钥，**不能覆盖安装官方签名版**（官方版需先卸载）；**v1.3 起本分支各版本包名与签名一致，可互相覆盖安装**。
- **不在官方版本安全线内**：上游自 v3.2 起对官方 Release 启用签名指纹核验，本分支不受该线覆盖。
- **不具备官方版完整能力**：上游受版权保护的 ONNX 识别模型与桔库开局库未随本分支分发，缺失时识别回退 YOLO、连线降级纯引擎。
- 中文播报需系统已安装并启用至少一个支持中文的 TTS 引擎。
- 仅供个人学习、复盘研究与技术交流，严禁用于正式比赛、网络对局平台等违反平台规则与法律法规的场景（详见 `DESIGN_BOUNDARIES.md`）。
